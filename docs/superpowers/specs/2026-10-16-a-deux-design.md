# À deux — conception

Application native iPhone en français, iOS 17 minimum, pour un couple. Carte blanche donnée par l’utilisateur, qui demande le maximum d’agents. Le projet part d’un dossier vide ; pas de travail existant à isoler.

## Expérience
Une interface chaleureuse crème, vert sauge et accents abricot. Navigation Aujourd’hui, Planning, Maison. Ajouter et modifier une tâche dans une feuille. Filtrer par personne, catégorie et état ; terminer une tâche ; retrouver l’historique et annuler une validation accidentelle. Les routines créent la prochaine échéance à leur validation. Un bilan d’effort de la semaine montre une contribution commune, sans score compétitif.

Premier lancement : noms des deux personnes, nom du foyer, choix de son identité sur cet appareil. Aucun exemple n’est inséré sans action explicite. Une action distincte propose des routines de départ. Rappels locaux facultatifs, demandés lors de leur activation.

## Données et partage
SwiftUI, bibliothèque Swift sans dépendance tierce. Cœur de domaine pur testable par Swift Package Manager. Core Data et NSPersistentCloudKitContainer avec magasins privé et partagé, partage CKShare d’un foyer et de ses relations. Identités stables personOne/personTwo, identité courante locale à chaque appareil. Une tâche ajoutée à un foyer partagé est affectée au même magasin que le foyer. Les objets partagés restent modifiables hors connexion ; Core Data gère les imports et exports iCloud.

Le mode local est utilisable sans config Apple ; activer explicitement iCloud après configuration du conteneur et des capacités. Pas de promesse de synchronisation active si le compte ou le conteneur est indisponible. Les erreurs sont présentées et permettent de réessayer. Invitation iCloud depuis Maison et réception via délégués UIKit. L’utilisateur invité sélectionne le foyer partagé et son identité locale.

## Contrat de modules
DeuxCore : TaskCategory (cleaning, groceries, laundry, admin, meals, other), Assignee (personOne, personTwo, anyone), TaskRecurrence (none, daily, weekly, monthly). HouseTask : id UUID, title String, notes String, category TaskCategory, assignee Assignee, dueDate Date, recurrence TaskRecurrence, effortMinutes Int, reminderEnabled Bool, createdAt Date, completedAt Date?. TaskCompletion : id UUID, taskID UUID, title String, completedBy Assignee, completedAt Date, effortMinutes Int, previousDueDate Date, recurrence TaskRecurrence. Tous Codable, Equatable, Sendable ; types Identifiable quand id. Initialisateurs publics avec valeurs par défaut raisonnables.
TaskRules.complete(task:by:at:calendar:) retourne (task: HouseTask, completion: TaskCompletion) ; refuse une tâche déjà terminée ; met completedAt pour tâche unique, avance dueDate et conserve completedAt nil pour routine. TaskRules.undo(task:completion:) restaure l’échéance antérieure. TaskRules.validate(_:) refuse titre vide et effort hors 1...480. TaskInsights calcule échéances du jour/en retard, semaine civile et minutes effectuées, sans compter deux fois les tâches récurrentes.

DeuxPersistence : @MainActor public final class HouseholdStore: ObservableObject. @Published public private(set) tasks [HouseTask], completions [TaskCompletion], householdName String, personOneName String, personTwoName String, isLoading Bool, errorMessage String?, cloudStatus String, hasHousehold Bool, availableHouseholds [HouseholdSummary]. @Published public var currentPerson: Assignee (persisté localement). init(inMemory: Bool = false, cloudEnabled: Bool = false). async load(); createHousehold(name:personOne:personTwo:) throws ; updateHousehold(name:personOne:personTwo:) throws ; saveTask(_:) throws ; deleteTask(_:) throws ; completeTask(_:at:) throws ; undoCompletion(_:) throws ; addStarterTasks() throws ; selectHousehold(id:) throws ; clearError(). name(for:) -> String. Propriétés publiques container NSPersistentCloudKitContainer et activeHousehold NSManagedObject?, sharedStore NSPersistentStore? pour pont CloudKit. Invitation : acceptShare(_ metadata: CKShare.Metadata) async throws. Partage : prepareShare() async throws -> CKShare ; persistShare(_:) async throws. Exposer cloudContainerIdentifier et cloudEnabled. HouseholdSummary id UUID, name String, isShared Bool.

DeuxUI : public struct DeuxRootView: View ; init(store: HouseholdStore, onShare: @escaping () -> Void = {}, onRequestNotifications: @escaping () -> Void = {}). Toutes les vues fonctionnent aussi sous macOS 14 avec gardes conditionnelles pour APIs iOS, afin de compiler avec le SDK disponible. Aucun type UI ne duplique le domaine. L’app iOS instancie et charge le store, présente le partage natif, reçoit les invitations, recalcule les rappels après modifications et passage au premier plan.

## Validation et limites
Tests de calendrier (récurrences, retards, mois courts, changement de semaine), validation, complétion/annulation et stockage/rechargement. Compilation macOS des modules partagés et analyse syntaxique Swift des fichiers iOS. Le SDK iOS et le simulateur ne sont pas présents : compilation iOS et test réel de CloudKit explicitement non validés ici. Documentation française d’installation, configuration Apple, test à deux comptes et limites.
